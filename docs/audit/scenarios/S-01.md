# S-01 Years of operation: dependencies two majors behind, original developers gone

Walked 2026-10-08 (Pass 3) against `main` `826b53e`. Method: `methodology.md` Appendix B. New findings are created in their home subject file; this file only walks and references.

## Walk

1. Five years on, Next.js, React, Clerk, Drizzle and Expo are each one or two major versions behind. A security advisory lands for one of them.
2. Nobody is told: there is no scheduled dependency or workflow-update control (F-SEC-004). The advisory is found by chance.
3. A new engineer clones the repository. The setup instructions describe an environment that does not exist (F-REL-006, F-TEST-004, F-AUTH-006) and the documents are long, partly duplicated and unindexed (F-DEVOS-003). Node and pnpm versions differ between CI, Vercel and the machine (F-REL-003).
4. They upgrade a major version. The only check against the real identity provider and database is manual and not in CI (F-TEST-002); pages are verified only by compilation (F-TEST-003). Migrations are never applied or drift-checked in CI (F-DATA-003).
5. They ship. A release is only a merge, with no deployment check or rollback steps (F-REL-001).

## Where it breaks

Steps 2 to 5, each already covered above. The strengths that help: frozen installs and a single `Validate` gate (F-REL-008), strict types and layering tests (F-CODE-005, F-TEST-006), and a ruleset on `main` (F-SEC-001, applied).
