# S-07 Prompt injection into the Claude workflow through an issue, pull request or web content

Walked 2026-10-08 (Pass 3) against `main` `826b53e`. Method: `methodology.md` Appendix B. New findings are created in their home subject file; this file only walks and references.

## Walk

1. The repository is public, so anyone can open an issue or comment. The workflow acts on mentions; who may trigger it is governed by a documented rule that contradicts the workflow itself (F-DEVOS-004).
2. Injected text asks the agent to read secrets, run a command or open a pull request. The job has a database address, write permissions and `Bash(pnpm *)`, `Bash(npx *)` style access that amounts to arbitrary code execution (F-SEC-002).
3. Output reaches `main` only through a pull request that needs the `Validate` check and a human merge (F-SEC-001, F-DEVOS-008). But review evidence is not kept (F-DEVOS-001) and a red CI is not treated as a stop signal for the agent (F-DEVOS-002).
4. Two agent runs can race (F-DEVOS-006).

## Where it breaks

Step 2 is the High finding (F-SEC-002). The ruleset (step 3) is the strongest mitigation and is in place.
