# S-04 Active external attacker against the web app and API

Walked 2026-10-08 (Pass 3) against `main` `826b53e`. Method: `methodology.md` Appendix B. New findings are created in their home subject file; this file only walks and references.

## Walk

1. Reconnaissance: the site is public; Previews are behind Vercel Authentication (F-SEC-011). No security headers (F-SEC-005).
2. Direct access: protected pages and APIs answer with a sign-in handshake or 401 and fail closed, in code and on the deployed site (F-AUTH-009). Authorization primitives deny by default (F-AUTH-010).
3. Any signed-in account reaches the admin and church areas today; the role model is undecided (F-AUTH-001). Nothing tests that route protection exists (F-TEST-001), so a regression would not be seen.
4. Abuse: no rate limiting (F-SEC-006); state-changing routes depend on cookie `SameSite` alone (F-AUTH-008); a deletion answers differently for "exists" and "not yours" (F-AUTH-007).
5. Detection: nothing alerts on the attack (F-OPS-001); few logs survive.
6. Injection and data theft: validation at the boundary, parameterized queries and server-only secrets (F-SEC-009, F-DATA-010).

## Where it breaks

At steps 3 to 5; all covered. Highest priority, because it is cheap and the test gap is proven by experiment: F-TEST-001 and F-AUTH-001.
